# 합성 평가와 회귀검사

실제 환자 자료를 읽거나 외부 모델 API로 문장을 전송하지 않고, 사람이 작성한 56개 합성 문장을 검사합니다. 학습·운영 성능 추정에 사용할 표본이 아니며, 정규식과 모델의 성공·실패를 재현하기 위한 작은 개발용 convenience set입니다. 구현과 동일한 문장으로 개발·평가한 부분이 있으므로 독립 검증 성능으로 제시하지 않습니다.

프로젝트 상위 디렉터리에서 실행합니다. 의존성은 README 지침대로 준비합니다.

```powershell
.\ClinicalTextDeid\.venv\Scripts\python.exe -m unittest discover -s ClinicalTextDeid/tests -v
.\ClinicalTextDeid\.venv\Scripts\python.exe -m ClinicalTextDeid.evaluate
```

영어 모델을 설치하지 않은 명시적인 규칙 전용 비교는 `-m ClinicalTextDeid.evaluate --detectors upstream rules`로 가능합니다. 기본 전체 자동검사는 로컬 Presidio/spaCy 모델까지 요구하며, 의존성 누락을 조용히 건너뛰지 않습니다. `--output-dir`은 합성 평가 결과의 저장 위치를 지정합니다. 평가 프로그램에 임의 환자 데이터 입력 옵션은 없습니다.

`evaluation/metrics.json`에는 탐지기별 총계·문장 층별 총계·case ID별 TP/FP/FN 및 정확 구간 오류가 있습니다. `evaluation/report.md`는 사람이 읽는 한국어 요약입니다. 현재 소스와 fixture 파일 SHA256 및 설치된 패키지 버전도 기록합니다. 변경 후 재실행하면 덮어씁니다. 평가 출력에는 원문이나 변환문, PHI 문자열, 키, nonce, 암호문, 캡슐을 저장하지 않습니다. fixture 원문은 전부 공개 가능한 합성 문장입니다.

## 탐지 비교

1. **upstream**: 라이선스 확인 후 번들한 공개 ko-pii의 변경하지 않은 `detect_all(original_text, include=DIRECT)` 호출입니다. upstream 자체 기본 `normalize=True`와 기본 제외 목록을 그대로 사용하며, **adapter의 추가 Unicode 정규화/원문 역매핑**과 임상 보충 정규식 및 영어 모델은 사용하지 않습니다. 원문 탐지 비교만 합니다.
2. **rules**: 실제 공개 ko-pii 코드에 원본 위치를 보존하는 Unicode 처리, 문맥을 명시한 이름·MRN·기관·운동 행사 정규식을 더한 구현입니다.
3. **hybrid**: rules에 실제 공개 Presidio/spaCy 로컬 영어 NER 및 선택된 구조 인식기를 더합니다. 영어 PERSON/LOCATION 탐지는 모델 기반이며, 한국어 NER/LLM/임베딩 일반화라고 주장하지 않습니다. 이메일은 연결 없이 동작하는 ko-pii 인식기를 사용합니다.

정답 구간은 `fixtures.json`에서 합성 원문의 unique literal과 유형으로 수동 표시했습니다. 평가에서 이를 원문 위치로 바꾸지만 `detect`/`transform` 호출에 힌트로 전달하지 않습니다. name anchor와 같은 문장 자체의 정보는 규칙이 읽을 수 있고, 정답 PHI 위치를 사전 제공하는 성능 수치가 아닙니다. fixture 파일의 이름은 일반적인 합성 이름으로 의도적으로 구성했으며, 실제 인물·주소와 일치하지 않는다는 통계적 검사를 뜻하지 않습니다.

문자 점수는 **Unicode code point 위치 집합**의 교집합과 차집합으로 계산합니다. `TP=predicted∩gold`, `FP=predicted−gold`, `FN=gold−predicted`, `P=TP/(TP+FP)`, `R=TP/(TP+FN)`, `F1=2TP/(2TP+FP+FN)`입니다. 겹치는 예측은 위치 집합에서 한 번만 셉니다. 숫자·한글 조합문자의 UTF-8 바이트 길이는 탐지 분모로 쓰지 않습니다. 분모가 없는 precision 등은 `null/n/a`이며 100%로 채우지 않습니다. 각 문장의 수를 합친 micro 점수입니다.

정확 구간 점수는 `(start,end,type)` 완전 일치만 TP로 셉니다. 한 글자 덜 가린 이름이나 유형이 다른 구간은 FN와 FP가 생깁니다. 서로 겹치는 유형을 합쳐 `MIXED_PHI`로 바꾸면 원래 gold 유형과 일치하지 않습니다. 유형 없이 경계만 완전히 일치한 별도 `strict_boundary` 점수도 JSON에 제공합니다. 문자 F1가 높아도 완전 식별자 제거가 보장되지 않는 차이를 보려는 것입니다.

직접식별자 **direct**와 기관·행사 **quasi**를 분리했습니다. 이 quasi 점수에는 숫자 나이·날짜·희귀 직업 조합 등 모든 준식별자가 들어있지 않습니다. all 문자 점수는 유형을 무시하며, direct/quasi 부분점수는 gold와 예측의 유형으로 각각 분류합니다. `MIXED_PHI`는 direct에 포함합니다. 이 분류 자체도 평가 정책이며 법적 익명정보 판정이 아닙니다.

## 복원과 의미 손상

rules와 hybrid 각각 56개 문장에 대해 direct 및 context_rules 정책을 따로 실행하여 112회씩 원문을 복원합니다. `restore(...) == original.encode('utf-8')`로 비교하므로 BOM, CRLF, 탭·공백·개행, NFD 한글, fullwidth, zero-width, 이모지의 바이트까지 확인합니다. byte-exact 성공은 내용 비식별화 성능이나 접근권한이 안전하다는 뜻이 아닙니다.

의미 보존은 API가 반환하는 자체 상태와 별개로 fixture에 명시한 유한한 의무를 확인합니다. 용량·단위·빈도, 명시 성별, 숫자 나이, 운동 시점, 증상·부정 문구 sentinel은 변환문에 그대로 있어야 합니다. 제한된 지원 가족력 문구에는 별도의 주체·부정·명시된 사건/사망 나이·치명 경과·조기 MI 규칙 결과와 출력 문구를 검사합니다. `father died from MI at 52`의 52는 출력에서 사망 나이로 유지하며, 이전의 MI 발병 나이가 52였다고 새로 추론하지 않습니다. 해당 나이에 MI로 사망했다는 문구에 조기 MI 규칙 결과를 붙이는 범위와, 별도의 발병 시점을 추론하는 일을 구분합니다. 지원 밖 가족 문장에서는 임의 가족력 일반화를 하지 않았는지 확인합니다. 성별을 명시하지 않은 이름에서 남성/여성을 만들면 실패입니다.

문맥 일반화는 `context_rules` 기본값으로 숫자 나이·운동 시점을 보존하며, 일반화 손실을 명시적으로 허용한 별도 자동검사에서만 이를 줄입니다. 가족력 원문 나이와 사망 정보는 일반화 정책에서도 유지합니다. 부모 API의 넓은 의미 검증을 대신하지 않으며 자유서술 주체·부정·치료 의미를 전부 검증하지 않습니다.

## 검사하는 경계와 실패

자동검사는 잘못된 키·문서/프로젝트/목적/반출 문맥, nonce·ciphertext·tag 변조, 공개문장/감사/정책/평가 변조, 다른 문서의 캡슐 교환을 거부하는지 확인합니다. 입력 크기·UTF-8·Base64·힌트 구간·정책 스키마 검사를 포함합니다. 겹치는 PHI가 일부만 치환되어 꼬리를 남기지 않는지, PHI 구간과 일반화가 교차할 때 PHI 우선 적용으로 변경한 가족력 사실을 철회하는지 검사합니다. 공개 payload allowlist에 내부 캡슐을 포함하지 않는지도 확인합니다.

NFD 이름의 빈 구간 및 원문 위치 역변환은 회귀검사합니다. 가족력 앞뒤 같은 문장에 부정·불확실·가정 cue가 있으면 좁은 일반화를 보류하고 검토 필요로 남깁니다. `Patient denies that father had MI at 52.`를 양성 가족력으로 변환하는 오류를 막는 검사와, 별도 문장의 증상 부정이 가족력 일반화를 잘못 막지 않는 검사를 포함합니다. 이 cue veto는 부정 NLP parser가 아니므로 가능한 모든 scope 표현을 지원하지 않습니다.

영어 공개 탐지기의 모델 추론은 DNS와 새 네트워크 연결을 차단한 상태에서도 동작해야 합니다. 모델 패키지 초기 설치와 공개 코드/문서 조사에는 네트워크를 사용하지만 합성 문장 변환·복원은 외부 API를 사용하지 않습니다.

CLI 통합 회귀검사는 새 프로세스에서 transform과 restore를 각각 실행합니다. 테스트 전용 임시 폴더에 전부 합성인 입력, 무작위 테스트 키, 내부 암호화 결과와 복원 파일을 잠시 만들며, 종료 시 모두 삭제합니다. 저장된 `evaluation/` 결과에 이 자료를 남기지 않습니다. 공개·내부 디렉터리 양방향 중첩, `..` alias, 복원 평문의 공개 디렉터리 저장 및 기존 파일 덮어쓰기를 거부하는지 확인합니다. 디렉터리 symlink 검사는 운영체제에서 허용될 때 실행하며, 현재 Windows 환경에서는 생성 권한 부족으로 skip되었습니다. skip을 성공으로 집계하지 않습니다.

같은 프로젝트·문서 문맥, 같은 길이의 다른 이름과 동일한 공개문장/감사 구간에도 캡슐 교환을 거부하는지 확인합니다. `transformation_id`가 AAD에 결합되어 원문이 달라도 외부 결과가 우연히 같은 경우를 구분합니다. 전체 결과와 그 캡슐을 함께 교체하는 저장소 공격까지 이 검사로 방지한다는 뜻은 아닙니다. 반복된 나이·운동 시점 중 한 번만 가려져도 횟수 기반 보존 검사에서 실패해야 합니다. 강제 힌트로 용량 `10 U`, 한국어 나이 `47세`, 임상 어휘 `당뇨`, 측정값 `Cr 1.2 mg/dL`를 잘못 치환한 경우 `failed` 및 `protected_clinical_fact_changed`를 반환하는지 검사합니다.

## 개발 중 발견과 최종 측정 구분

처음 측정에서 `false_en_clinical`의 **Boston brace** 장치 문구 중 Boston을 ADDRESS로 가리는 오류가 발견되어 임상 sentinel 의무가 실패했습니다. 이후 문맥을 가진 eponym/brace 및 측정값/친족 어휘에 완전히 들어오는 PERSON/ADDRESS 후보만 제외하는 좁은 보호 규칙을 추가했습니다. 동일한 56개 문장을 유지하고 관련 독립 회귀문장을 추가했습니다. 최종 fixture 검사는 임상 의무 134/134를 통과하지만 개발셋 오류를 찾아 수정한 결과이며, 독립 holdout 성능 향상을 입증하지 않습니다.

수정 전 실행 출력에서 관찰한 집계·case ID만 `evaluation/development_observations.json`에 남겼습니다. 당시 전체 소스 snapshot은 보존하지 않았으므로 재현 가능한 역사 벤치마크로 쓰지 않습니다. 초기 의미 의무는 125개였고 이후 가족력 출력의 조기 여부 검사 9개를 더해 현재 134개가 되었으며, 분모 변화 자체를 모델 개선으로 해석하지 않습니다. baseline 설명은 `no adapter normalization`이며 upstream `detect_all`의 자체 기본 정규화는 두 실행 모두 동일합니다. 현재 `metrics.json`과 `report.md`가 최종 측정이고, 초기 의미 실패를 현재 실패와 혼동하지 않습니다.

명시 이름 anchor가 임상 eponym 문맥과 충돌하는 `Name: John Smith syndrome`에서는 명시된 이름 치환이 우선입니다. 의료 어휘 보호가 이름을 그대로 공개하게 만들지 않으며, 동시에 임상 guard 손실 검사에서 `failed`로 표시하여 모호한 문맥 검토를 요구합니다. 사전 제외 어휘와 실제 사람 이름의 동음이의어, 별칭/언어 간 동일인 연결은 해결되지 않으며 단순 어휘 보호는 이름 누락을 만들 수도 있습니다.

현재 자동검사는 총 45개 중 44개 통과, 디렉터리 symlink 검사 1개 skip입니다. 루프 안에서 112개 정책별 복원 및 여러 부정·암호변조 조건을 추가로 검사하지만 이를 독립 테스트 수로 부풀리지 않습니다. 평가 문장 수는 56개이며 회귀검사 전용 문장은 fixture 분모에 더하지 않았습니다.

알 수 없는 소문자 이름, 단일 이름, 한국어 분리된 이름, 서술형 주소, 단어로 풀어 쓴 이메일, 동형 문자 등의 **실패 사례를 의도적으로 유지**합니다. 영어 NER는 의료 장치 문구의 지명을 주소로 오인하는 등 임상 손상을 일으킬 수 있습니다. 보고서는 실제 발견한 FN/FP와 임상 sentinel 손상을 모두 남깁니다. upstream NFD raw offset과 기관/행사 누락 등도 평가에 그대로 포함합니다. 모든 실패를 제거했다는 테스트가 아니며, 지원되지 않는 표현은 `assessment.unsupported`, `warnings` 및 다음 단계 검토로 전달해야 합니다.

현재 측정값은 [합성 평가 보고서](evaluation/report.md)에서 확인할 수 있습니다. 작은 합성 점수와 SNUBH 연구의 KoBERT 토큰 F1 등 다른 데이터·모델·단위의 수치를 비교하지 않습니다. 더 넓은 사용 전에는 접근이 허가된 독립 holdout 자료에 대한 다기관·다문체 검증과 실제 운영 권한·키관리·로그 점검이 필요하며, 이 시제품의 결과 자체는 반출 승인이 아닙니다.
