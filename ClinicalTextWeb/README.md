# ClinicalText 웹 시연

기존 `ClinicalTextDeid`와 `ClinicalCDSGateway`를 연결한 **로컬 웹 프로토타입**입니다. 현재 기본 화면은 기존 LLM을 이용한 목적별 처리 모드입니다. 진단명 보호 규칙과 서버 측 합성 예제 검증 확장을 추가했으며, 실제 환자기록의 반출 제한은 유지합니다.

## 현재 연결 — 2026-10-28

**서버 연결을 복구했고 최신 정책으로 실제 GPU 시험을 완료했습니다.** 정상 사례 5개가 임상 검증·승인·서명 반출까지 통과했고, 의도적으로 손상한 사례 8개를 모두 차단했습니다. [최신 실제 실행 보고서](docs/evaluation-2026-10-28-final/report.html)를 확인하세요.

사용자가 지정한 SSH 별칭 `server`의 RTX 3090에서 Ollama **qwen3:30b (30B-A3B, 약 19 GB)**를 실행합니다. 모델 전체의 GPU 적재를 확인했으며 노트북에서 LLM 추론을 실행하지 않습니다. 요청했던 `qwen3:4b-instruct`도 설치되어 있습니다. 모델을 크게 하는 것과 함께 아래 편집·검증 제약을 보완했습니다. 새 학습은 없습니다.

`start-demo.cmd`가 SSH 연결을 복원한 뒤 웹을 엽니다. 웹 → `127.0.0.1:11435` → SSH → 서버 루프백의 Ollama로 연결하며 인터넷에 모델 서버를 공개하지 않습니다. 연결 실패 시 CPU로 자동 전환하지 않습니다. `.runtime/gpu-connection.json`과 `.runtime/local-model.json`에는 연결 설정만 저장합니다. 5분간 요청이 없으면 모델이 GPU에서 내려가므로 첫 요청에는 적재 시간이 추가됩니다. 웹의 **시연 종료**가 서버 Ollama와 SSH 프로세스까지 종료하는 것은 아닙니다.

현재 정상 처리는 **3회 호출**입니다. ① 목적별 보존 조건·원문 수정안, ② 원문과 변환문의 임상관계 대조, ③ 변환문만 보는 잔여 개인정보 점검입니다. 코드가 원문 편집 위치, 근거 인용, 수치·부정·시간·가족 주체와 원문 식별정보 잔존을 추가 검사합니다. 같은 모델의 별도 호출은 통계적으로 독립된 검증기가 아닙니다. 실패 시 최대 2회 시도한 뒤 보류합니다.

등록 합성 예제는 모식도·한영 혼용·수술·신생아·약물 5개입니다. **임상 날짜 정책 수정:** 실제 수술 날짜 `2023년 3월 10일`과 `수술 3일 후`를 함께 보존합니다. `[수술일]` 치환도 정보 손실로 검사합니다. 생년월일·행정 날짜와 임상 사건의 날짜를 구분하며, 날짜와 원래 사건의 연결도 확인합니다. 예제는 환자 나이·직업·기관·행사를 일반화하고 부친의 52세 심근경색 사망을 보존합니다. 날짜 인식은 명시적 한국어/영어 사건과 제한된 날짜 형식에 대한 구현으로, 모든 임상 문맥을 해결한 것은 아닙니다.

과거력의 연도도 보존하며, 행사명 일반화 후에도 원래 시점과 증상의 연결을 확인합니다. 날짜 역할을 확인하지 못하면 자동 삭제하지 않고 보류합니다. 개인정보 검사는 명시적 분류값으로 실제 식별정보·구체적 조합 위험·일반/임상정보·판단 불가를 구분하고, 실제 출력 인용을 확인합니다. 조합 위험이나 판단 불가는 계속 보류합니다. 이 검사는 외부 데이터베이스 연결에 의한 재식별 위험이나 익명성을 측정하지 않습니다.

최신 결과: [실행 보고서](docs/evaluation-2026-10-28-final/report.html), [검증 기록](docs/VALIDATION.md), [오픈소스 적용 범위](docs/OPEN_SOURCE_BASES.md). 웹 기능시험 54개와 실제 GPU 정상 사례 5개·오류 사례 8개를 구분합니다. LLM은 일부 날짜 오류를 놓쳤고 독립 코드 검사가 차단했습니다. 실제 환자자료·전체 임상 정확도·재식별 위험 해소를 보증하지 않습니다. 원문 조회는 권한 검사 API까지 시험했고 웹 복원 버튼은 아직 없습니다. 이전 실패와 정책 수정 전 보고서도 보존합니다.

서버 작업은 SSH 종료 후에도 계속되도록 실행했습니다. `check-server-results.cmd`를 실행하면 현재 작업 상태와 작성한 합성 시험 결과를 이 PC로 가져옵니다. `.runtime/remote-background-job.json`에 작업 위치와 소스 묶음 해시를 기록하며 복원키·인증키는 가져오지 않습니다.

## 시작

Windows에서 **[start-demo.cmd](start-demo.cmd)를 더블클릭**합니다. 기존 가명처리 프로젝트의 Python 환경을 사용하므로 추가 설치가 필요 없습니다. 기본 주소는 **http://127.0.0.1:8765**입니다. 이미 실행 중이면 해당 화면을 다시 엽니다. 사용이 끝나면 화면 우측 상단의 **시연 종료** 또는 실행 창의 `Ctrl+C`로 종료합니다.

작업 폴더에서 직접 실행할 수도 있습니다.

```powershell
& '.\ClinicalTextDeid\.venv\Scripts\python.exe' -m ClinicalTextWeb.launch
```

포트가 사용 중이면 `--port 8766`처럼 다른 포트를 지정합니다. 웹 서버는 127.0.0.1에만 연결합니다. LLM 처리는 별도 모델 서버 또는 사용자가 설정한 API가 필요합니다. 시작 시 새로 학습하지 않습니다.

## LLM 연결

화면 우측 상단의 **LLM 연결 설정**에서 다음 중 하나를 지정합니다.

- **Ollama:** 로컬 서버 주소(기본 `http://127.0.0.1:11434`)와 설치된 모델명.
- **OpenAI 호환 서버:** LM Studio·vLLM·기관 API의 기본 주소(예: `http://127.0.0.1:1234/v1`)와 모델명.
- **OpenAI API:** `https://api.openai.com/v1`, 사용할 모델명과 API 키. API 키는 채팅 대신 설정 화면에 입력합니다.

검증 모델을 별도로 지정할 수 있습니다. 생략하면 같은 모델을 **별도 요청**으로 호출하며, 두 호출의 오류가 통계적으로 독립적이라고 주장하지 않습니다. 연결 테스트에는 환자기록 없이 짧은 확인 요청만 보냅니다. 키는 서버 메모리에만 저장하고 화면 응답·반출 파일·로그에 포함하지 않습니다.

외부 HTTPS API를 선택한 경우, 실제 원문과 연구 목적이 해당 서버에 전송됩니다. 기록과 목적지에 대한 확인란을 선택해야 실행되며 합성 문서로만 시연합니다. **모델 미연결·응답 오류 시 규칙 처리로 자동 대체하지 않습니다.** 비교를 원하면 처리 방식에서 규칙 모드를 명시적으로 선택합니다.

## 시연 순서

1. LLM을 연결하고 **연결 테스트**를 실행합니다. LLM 없이 오탐 수정만 확인하려면 **기존 규칙 처리 — 비교용**을 선택합니다.
2. **모식도 예시**, **한영 혼용**, **수술 기록**, **신생아 기록**, **약물 기록** 중 합성 예제를 불러옵니다.
3. 연구 목적과 보존 항목을 확인하고 **가명처리·검증**을 실행합니다.
4. 목적별 임상관계, 원문·변환문 근거, 별도 검증 결과를 확인합니다.
5. 검토 확인란을 선택한 뒤 **검토 결과 승인**, **승인 후 반출**을 누릅니다. 승인 유효시간은 2분입니다.
6. 직접 입력한 비등록 기록은 결과를 볼 수 있지만 기관 검토 전까지 반출을 보류합니다.

연구 목적, 원문, 보존 항목 또는 필수 구절을 변경하면 화면의 이전 결과와 승인이 무효화됩니다. 같은 가명처리 결과라도 연구 목적에 수술·약물·가족력 등이 포함되면 필요한 검사 항목을 추가합니다. 원하는 원문 구절을 직접 필수 조건으로 지정할 수도 있습니다.

## 실제 구현과 범위

- LLM 모드: 기존 탐지기의 후보와 연구 목적을 LLM에 전달하여 보존 조건·진단명·식별정보 수정 구간을 구조화하여 받습니다. 원문 구절과 등장 위치를 코드가 확인하고 해당 구간만 치환합니다. 별도 LLM 요청으로 관계 보존·누락·추가·모순·잔여 식별정보를 검사합니다. 실패 시 원문 기준으로 최대 2회 시도합니다.
- 근거 검사: LLM의 원문·변환문 인용이 실제 존재하는지, 검사 항목이 누락·중복되지 않았는지 확인합니다. 진단 구절·수치·용량·부정 표현은 규칙으로 추가 검사합니다. LLM의 자신감 점수만으로 통과시키지 않습니다.
- 규칙 비교 모드: 기존 `ClinicalTextDeidAdapter`의 hybrid 경로와 제한된 근거 표현 비교를 사용합니다. LLM 호출이 없는 모드임을 화면에 표시합니다.
- 진단명 오탐 수정: `Respiratory failure of newborn`, `Metabolic acidosis`, `Hypoxic ischaemic encephalopathy of newborn` 등의 **문구 안에서** 잘못된 PERSON 후보를 보호합니다. 해당 단어를 전역 예외로 만들지 않으며, 명시적 이름 필드의 식별정보는 계속 처리합니다. 진단명이 손상되면 사용자가 선택하지 않은 경우도 검증 실패로 표시합니다.
- 승인·반출: 서버가 보관한 목적·조건·결과의 해시와 기존 게이트웨이의 내용 승인, 정책 재검증, 일회 반출을 사용합니다. 브라우저가 보낸 승인 주장이나 수정한 결과를 신뢰하지 않습니다.
- LLM의 임상 해석·누락 검출·재식별 위험 평가에는 오류가 있을 수 있습니다. **서버가 작성·등록한 합성 원문만** 검증을 통과하면 승인·반출할 수 있습니다. 비등록 기록은 LLM 검증을 통과해도 보류합니다. 임의 입력을 승인된 원문으로 자동 등록하는 API는 없습니다.
- 제출·검토·반출 역할은 기존 로컬 시제품의 역할 토큰으로 호출합니다. 하나의 시연 화면이 역할을 대행하며, 실제 기관 사용자 인증이나 별도 담당자 분리를 구현한 것은 아닙니다.
- 반출은 이 컴퓨터의 임시 외부 폴더와 브라우저 다운로드를 이용한 모의 반출입니다. 실제 CDS·병원망·N2SF 인증과 연결되지 않습니다.
- 반출 JSON은 기존 공개 스키마와 서명만 포함합니다. 원문, 복원키, 대응표, 자유입력 연구 목적, 내부 검사 근거는 포함하지 않습니다. 서명 검증용 공개키는 별도로 저장할 수 있습니다. 이는 복원키가 아닙니다.
- 세션별 결과는 메모리에, 기존 게이트웨이의 원문은 임시 폴더에 암호화하여 보관합니다. 브라우저 저장소에는 기록을 저장하지 않습니다. 정상 서버 종료 시 임시 폴더가 정리되며, 비정상 종료 후 잔여 폴더 자동 정리는 구현하지 않았습니다. 다운로드 파일은 사용자가 보관합니다.

## 검증

```powershell
& '.\ClinicalTextDeid\.venv\Scripts\python.exe' -m unittest discover -s ClinicalTextWeb/tests -v
```

실제 hybrid 호출 → 보존 검사 → 승인 → 서명 반출, 승인 전 반출 거부, 개인정보와 필수 구절 충돌, 지원하지 않는 기록 보류, 입력 변경 후 승인 취소, 목적·검토 해시 변경 거부, 세션 분리, 동시 반출 1회, HTTP Origin·CSRF·내부 파일 접근 제한을 검사합니다. 수치·단위·부정·시간 손상과 반복 표현 손실을 별도로 검사합니다.

초기 웹 시제품과 최신 결과는 [검증 기록과 화면](docs/VALIDATION.md)에 구분합니다. 단위·프로토콜 시험에는 시뮬레이션 응답을 사용하며 **실제 GPU 모델 시험과 구분**합니다. 합성 사례의 실제 실행은 임상 성능 평가를 대신하지 않습니다.

[관련 공개 구현과 설계 근거](docs/OPEN_SOURCE_BASES.md): ko-pii·Presidio는 실제 탐지에 사용합니다. local-llm-deid의 원본 MIT 모듈·추출 프로토콜은 비교 실험에서 실제 호출합니다. RUPTA와 KatherLab은 구조를 참고한 별도 구현입니다. 해당 프로젝트의 공식 성능 재현이 아닙니다. `python -m ClinicalTextWeb.compare_approaches --help`에서 비교 실행 옵션을 확인할 수 있습니다.
